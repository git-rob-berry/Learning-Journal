## The Relational Data Model

**Primary Key** - Primary key is a unique identifier for records in a table. No two records can have the same primary key.  
**Foreign Key** - Foreign keys are fields in a table that match the primary key of another table, creating a link between the two tables.  

> Primary and Foreign keys are the linchpins that hold our database together, enforcing integrity and enabling efficient data management. Without them, our database would be a set of disorganised data.

## Schemas and Metadata

### Types of Schema

#### 🗄️ Database Schema

**What it is**  
A skeletal structure representing the logical view of a database.

**What it does**  
Describes the shape of data and how it relates to other models, tables, and databases.

**Examples**
- Star schema
- Snowflake schema
- Fact constellation schema (galaxy schema)

---

#### 💾 SQL Schema

**What it is**  
A type of database schema that encompasses functions, indexes, tables, and views, using **SQL (Structured Query Language)** to define the schema.

**What it does**  
Helps define database objects at the logical level.

**Example**  
A table made up of columns and rows, with **primary keys** and **foreign keys** representing relationships between tables.

---

#### 🤖 AI Schema

**What it is**  
A framework that standardises how AI models interact with structured data.

**What it does**  
Defines the structure and types of data that an AI model can understand or produce.

**Example**  
For weather prediction, an AI schema might define fields such as `temperature` and `humidity`.

An AI model could then produce:

```json
{
  "temperature": 20,
  "humidity": 80
}
```

Because the output follows a defined schema, other systems can easily understand and use it.

---

#### 🔎 SEO Schema

**What it is**  
Metadata that helps web crawlers understand the meaning and relationships between people, products, places, and other things on a webpage.

**What it does**  
Can improve how webpage content appears in search engine results, including images, videos, FAQs, and other rich results.

**Example**  
**Schema markup** added to HTML to provide extra context and structured information about a webpage.

---

#### 🔌 API Schema

**What it is**  
A structured definition of how an **API (Application Programming Interface)** works and how other systems can interact with it.

**What it does**  
Describes API operations, endpoints, expected inputs and outputs, and methods such as `GET`, `POST`, `PUT`, and `DELETE`.

**Examples**
- OpenAPI Specification
- API description languages

---

#### 🧠 Psychology Schema

**What it is**  
A mental framework that helps organise knowledge and guide cognitive processes and behaviour.

**What it does**  
Helps individuals understand and predict what they can expect from experiences, people, objects, and situations.

**Examples**
- Event schemas
- Object schemas
- Person schemas
- Self-schemas
- Social schemas

## SQL Database Comparison

### PostgreSQL vs Amazon Redshift

#### 🐘 PostgreSQL

- A widely used, **open-source relational database management system (RDBMS)**.
- Known for its **robustness and flexibility** when handling complex SQL operations.
- Well suited to general-purpose relational database workloads.
- Its open-source nature provides:
  - **Transparency** into how the software works.
  - **Flexibility** to customise the database.
  - **Community-driven development** and innovation.
  - Reduced risk of **vendor lock-in**.

---

#### ☁️ Amazon Redshift

- A **cloud-based data warehouse** designed for large-scale data analytics.
- Optimised for **OLAP (Online Analytical Processing)** workloads.
- Uses features such as:
  - **Columnar storage** to efficiently analyse large datasets.
  - **Parallel query execution** to process analytical queries at scale.
- Integrates closely with other **AWS services**, making it particularly useful for organisations already using the AWS ecosystem.

---

#### ⚖️ Key Differences

| Area | PostgreSQL | Amazon Redshift |
|---|---|---|
| **Primary purpose** | General relational database | Large-scale data warehousing and analytics |
| **Typical workload** | General SQL/database operations | OLAP and analytical queries |
| **Storage approach** | Traditional relational database storage | Columnar storage |
| **Scaling analytics** | Less specialised for very large analytical workloads | Designed for large-scale parallel analytics |
| **Open source** | Yes | No, AWS-managed service |
| **Ecosystem** | Flexible across different platforms | Closely integrated with AWS |

---

#### 🔍 Choosing a Database System

When comparing database technologies, consider:

- **Purpose** – transactional/general database operations vs large-scale analytics.
- **Performance** – how efficiently the system handles the expected workload.
- **Cost** – open-source hosting costs vs managed cloud service costs.
- **Scalability** – how well it handles increasing amounts of data.
- **Integration** – compatibility with existing tools and cloud services.
- **Vendor lock-in** – how dependent the organisation becomes on a particular provider.
- **Customisation** – how much control is available over the database system.

---

#### 🧩 SQL Standards and Compatibility

- Both PostgreSQL and Redshift support **SQL**, but their implementations are not identical.
- Differences can exist in:
  - SQL syntax and dialects.
  - Functions and extensions.
  - Supported database features.
- Understanding these differences is important when:
  - **Migrating data** between database systems.
  - **Integrating** multiple systems.
  - Reusing existing SQL queries or applications.
- Greater adherence to common SQL standards can make migration and integration between database technologies easier.

---

#### 💡 Key Takeaway

- **PostgreSQL** is a flexible, open-source relational database suited to a wide range of database workloads.
- **Amazon Redshift** is specifically designed for **large-scale cloud data warehousing and analytics**.
- The best choice depends on the organisation's **workload, scale, existing technology ecosystem, costs, integration requirements, and long-term strategy**.
